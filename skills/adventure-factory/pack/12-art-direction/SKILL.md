# Art Direction

## Instructions

**Creator control.** Use the creator's approved scope. Ask before introducing a gameplay mechanic or mandatory story structure; an unattended run must omit unapproved additions. Adventure clocks, countdowns, forced deadlines, timed escalation and substitute pressure tracks are excluded from this build. Never add them during generation, audit or repair, or penalize exploration/rest with a timer. Estimated session length, historical dates and ordinary rules durations are not adventure timers.

Provide consistent project art direction and subject-specific prompts grounded in canonical bodies, equipment, architecture and locations. Distinguish specifications/prompts from completed assets. Do not claim a cover, portrait, token, reference image or commercial right exists merely because a prompt was written. Credits, source, licensing evidence and rights review for each actual image are supplied and checked separately by the creator.

State what is true. Only say what something is NOT when players would reasonably assume it. Keep production_notes outside customer-facing prose.

## Inputs: exact selectors

- `world`: `visual_style`
- `npcs`: `npcs.*.id`, `npcs.*.name`, `npcs.*.appearance`, `npcs.*.portrait_prompt`
- `creatures`: `creatures.*.id`, `creatures.*.name`, `creatures.*.description`
- `items`: `items.*.id`, `items.*.name`, `items.*.appearance`
- `maps`: `maps.*.id`, `maps.*.theme`, `maps.*.prompt`

Only the declared creator spec fields and named prerequisite keys in `skill.json` are supplied. Missing inputs fail explicitly. Oversized context is not silently truncated.

## Output contract

Return the exact shape in `output.schema.json`. The schema is executable and authoritative; do not rename its top-level fields. Local validation is mandatory for every provider; native JSON-schema output is used only when explicitly configured. Bad JSON/schema replies receive bounded correction attempts with the actual rejected reply and error. Valid raw responses are saved before modification.

Owns: `art_direction`. Execution: `ai` / `art_direction`.

## Art plan "generated" (host-side, 0.11.2)

This section documents what the host does with this Skill's output; it is not sent to the model, and the model-facing Instructions above are unchanged.

`art_plan` may be `none`, `commissioned`, `licensed_stock` or `generated`. With `generated`, the creator commissions AI images from an image model. The host, not this Skill, plans and prompts them:

- `art-plan` builds `ART/manifest.json` (the `art\` folder on Windows): one slot for the cover, one opener per chapter, one illustration per location, one portrait per NPC, one illustration per creature, and optionally items (`--items N`, default 0). Each slot has a stable id, kind, target entity id, aspect ratio, placement (full-page, half-page or column-width), model, image size, prompt and negative prompt.
- Every prompt is built the same way so the art matches: the subject comes from canonical public fields (names, appearance, clothing, descriptions, chapter openings, location sight lines, `portrait_prompt`/`token_prompt`/`art_prompt`, and any matching `*_art_specs` entry), followed by this Skill's shared style: `master_style`, `rendering_style`, `palette`, `lighting`, and per kind `architecture`, `clothing`, `monster_design_language` or `materials`, plus `magic_language` and the spec `tone`. The cover uses `cover_spec.subject` and keeps `cover_spec.title_space` clear. `do_not_include` plus a fixed list (no lettering, logos, watermarks or frames) becomes the negative prompt, sent as an "Avoid:" line.
- Nothing is generated by planning. `art-generate` quotes by default and generates only with `--approved`; each finished slot records file, SHA-256, model id, provider, time and the exact prompt used. A prompt that no longer matches the current text must be re-planned before generating.
- A prompt is still a specification, not a completed or cleared asset. Release needs the declared plan, a reviewed AI-use disclosure that mentions the generated art, and a hash-bound rights record for every placed image.

## Verification and failure behavior

A successful call is not publication approval. Post-skill checks feed the repair controller; unrepairable/schema failures retain the checkpoint and raw evidence. Audit and repair pointers address canonical state (for example `/npcs/npcs/0/speech_style`), not a PDF page. Protected human values, IDs and unrelated fields may not be overwritten. Upstream changes invalidate affected output and audit hashes.

See `docs/REVIEW_RESPONSE.md` and `docs/ENFORCEMENT_MATRIX.md` for code-vs-prompt boundaries and regression tests. Quality, originality, play balance, art rights and visual proof are not guaranteed by field presence or a pass label.
